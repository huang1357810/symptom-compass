## 1. 自然语言识别漏掉"手上脚上起了疹子"

**现象**：输入「手上脚上起了疹子，嘴里也有溃疡」，一个症状都没识别出来。

**定位**：把页面 `<script>` 抽出来在 Node 里跑 `parseSymptoms()`，输出为空数组 → 说明是词表问题，不是解析逻辑问题。

**根因**：词表里手足皮疹只有"手上有疹子"，原文是"手上**脚上**起了疹子"；另外"起了"的"了"没被当作虚词，导致"起疹子"也对不上。

**修复**：
- 补别名 `手上脚上起疹`、`手脚起疹子`
- 把"了"加入虚词表 `NL_FILLERS`

**验证**：12 个用例 12/12 通过。

## 2. 手动取消的症状，编辑文字后又被自动加回

**现象**：输入一句话自动勾选 3 项 → 手动点掉"流涕" → 再改一个字 → 流涕又回来了。

**定位**：浏览器里逐步操作，观察 `.chip.on` 数量变化；读 `applyParsed()` 发现它只判断"是否已在 selected 里"，不区分"用户主动取消"。

**根因**：`toggle()` 只删了 `autoIds`，但 `applyParsed()` 会把"未选中且被识别到"的症状重新加进去。

**修复**：新增 `manualIds` 集合；用户手点过的症状进入该集合，`applyParsed` 直接跳过。

**验证**：同一句话重复识别，不再加回；`clearAll()` 会重置这个集合。

## 3. 搜索框搜"闹肚子"没有任何结果

**现象**：用户反馈在搜索框输入"闹肚子"筛不出症状。

**定位**：搜索处理函数里写的是 `ch.textContent.toLowerCase().includes(q)`——只比对症状**名称**。

**根因**：别名表只服务于自然语言识别，搜索走的是另一条路。

**修复**：新增 `symptomMatchesQuery(id, q)`，同时查名称和别名；搜索框改为调用它。

**验证**：搜索"闹肚子 / 窜稀 / 脑壳疼 / 打摆子"均能命中；清空后 78 个症状全部恢复。

## 4. `心口疼` 到底算胸痛还是胃痛

**现象**：测试用例期望"心口疼 → 上腹痛"，实际输出"胸痛"。

**定位**：词表去重规则是"同一短语只保留先出现者"，而 `chest_pain` 在症状定义里排在 `epigastric_pain` 前面。

**根因**：这不是代码 bug，是**语义歧义**。

**决策**：保留"→ 胸痛"。理由：心口疼可能是心梗，**宁可过度预警**，让人白跑一趟急诊好过漏诊。

**验证**：NLU 单指"胸痛"，搜索时两个症状都会出现，由用户判断。

## 5. Netlify 部署成功，线上却一直是旧版

**现象**：拖拽部署后 Deploys 显示 Published，但页面还是旧内容；换浏览器、加参数都没用。

**定位**：`curl` 拿到的 HTML 长度和旧版一致；检查 `sw.js` 发现缓存名一直是 `symptom-checker-v1`，且 fetch 策略是"缓存优先"。

**根因**：Service Worker 缓存优先 → 老访客永远读缓存，**部署多少次都不生效**。

**修复**：
- 页面导航改为**网络优先**，断网时才回退缓存
- 缓存名升到 `mingbian-kangtu-v3`，激活时清理旧缓存

**验证**：改文件后刷新立即生效；断网刷新标题正常、78 个症状仍在。

## 6. `git push` 报 Connection was reset

**现象**：浏览器能打开 github.com，但 `git push` 超时/重置。

**定位**：`Invoke-WebRequest` 访问 GitHub 返回 200，git 却连不上 → 怀疑代理。查注册表发现系统代理 `127.0.0.1:7897`（Clash），而 git 默认不读系统代理。

**根因**：浏览器走系统代理，git 直连被重置。

**修复**：`git config --global http.proxy http://127.0.0.1:7897`。

**验证**：配置后推送成功；日志显示 `8f4e549..5d12ee5 main -> main`。

## 7. 手机端结果页两个按钮错位

**现象**：430px 宽度下，"导出给医生"和"修改症状"折成两行且不对齐。

**定位**：`.sec-head` 是 flex + wrap，标题 + 标签 + 两个按钮在窄屏放不下，第二个按钮被挤到下一行。

**修复**：移动端把 spacer 强制换行（`flex-basis:100%`），两个按钮各占 50%。

**验证**：截图确认一行两个、等宽。

## 8. 年龄分级上线后，用药提示不显示

**现象**：70 岁 + 抗凝药 + 头痛，结果页没有任何用药提示。

**定位**：控制台报 `renderSafety is not defined`——`showResults()` 里调用了它，但函数根本没写（只写了纯函数 `safetyCheck`）。

**根因**：新增功能时"调用先写了，实现漏了"，且当时没有覆盖到这一层的测试。

**修复**：补 `renderSafety()`，负责把 `safetyCheck` 的结果渲染成提示卡。

**验证**：三个场景——老人+抗凝（红色三条）、儿童（按体重提示）、婴儿发热（红色分诊）全部通过。

---

## 9. 测试用例本身写错了

**现象**：`3 个月 + 布洛芬` 用例失败，提示没有触发"6 个月以下禁用"。

**定位**：用例写的是 `age: 0.8`（10 个月），大于 0.5 岁，规则本就不该触发。

**根因**：**测试写错了，不是代码错了**。

**修复**：改成 `age: 0.3`（3.6 个月），规则正常触发。

**意义**：这条特别值得写进材料——它说明我们不是"测试全绿就完事"，而是会检查"测试本身对不对"。

## 10. 3D 器官标签全堆在一个点上

**现象**：给 3D 视图加器官标签后，6 个标签（心/肺/胃/肝/肾/肠）全叠在画面中央，只有一个看得见。

**定位**：在查看器里打印每个器官的包围盒中心，发现 6 个值完全相同，都等于身体的中心 `(0, 0.88, 0)`。再用 Node 直接解 GLB 的 JSON 块，看到每个器官的 POSITION accessor 都写着 `min:[-0.4,0,-0.3] max:[0.4,1.75,0.3]`——全是**身体**的包围盒。

**根因**：模型生成脚本 `tools/build-body-glb.js` 写 accessor 时把包围盒写死了，7 个网格共用同一组 min/max。three.js 的 GLTFLoader 会直接采用 accessor 的 min/max 作为 `geometry.boundingBox`，于是每个器官都被认为占满全身。

**修复**：
1. 生成器改为按顶点真实坐标计算 min/max
2. 查看器加防御：`computeBoundingBox()` 按顶点重算一次（换第三方模型时也能兜住）

**顺带发现并修复**：
- 3D 视图被塞在 168px 宽的 SVG 栏里，模型被压得很小 → 3D 模式下让舞台占满整行
- `toggle()` 没有调用 `updateBodySelection()`，从面板点症状时，2.5D 热点和 3D 高亮都不会更新 → 补上调用

**验证**：6 个标签分散在正确位置；点标签能选中器官；选中症状后器官高亮 + 标签变色；切回 2.5D 热点同步高亮。
