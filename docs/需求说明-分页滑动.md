# 需求说明：症状录入改为左右滑动的三页

> 交给 CodeArts / 码道执行时，把本文全文粘贴过去即可。
> 项目：明辨康途（单文件 Web 应用），主文件 `site/index.html`。

---

## 1. 背景与目标

当前「1. 你有哪些不适？」把 **一句话描述、快速开始、人体部位图、搜索、全部症状折叠、年龄与长期用药** 全部堆在一屏，手机上要滚动 1.5 屏才能看到提交按钮，老年用户容易迷路。

**目标**：拆成 3 个可左右滑动的页面，每页只做一件事；底部/顶部有页签，可直接点，也可滑动切换。已选症状在所有页之间共享。

---

## 2. 页面结构

| 页 | 标题 | 内容 | 主操作 |
| --- | --- | --- | --- |
| **P1 说症状** | 说说哪里不舒服 | 一句话输入框 + 识别按钮 + 快速开始（感冒样/吃坏肚子/头痛头晕） | 「下一步」 |
| **P2 指位置** | 点一下不舒服的位置 | 2.5D 人体图（皮肤/肌肉/骨骼/内脏图层）+「3D 视图」按钮 + 搜索框 + 「查看全部 81 个症状」折叠 | 「下一步」 |
| **P3 确认** | 确认并开始 | 已选症状清单（可单个删除）+ 年龄 + 长期用药 + 清空 | 「查看可能情况」 |

**页签**：`① 说症状 · ② 指位置 · ③ 确认（已选 N 项）`

---

## 3. 交互要求

### 3.1 滑动
- 水平滑动手势切换页面，松手后必须**整页吸附**，不允许停在两页之间。
- **纵向滚动与横向滑动分离**：纵向优先。只有横向位移明显大于纵向（建议 `|dx| > |dy| * 1.5` 且 `|dx| > 40px`）才切换页面。
- 在 **3D canvas** 上滑动时，不切换页面——那是旋转模型（canvas 已有 `touch-action:none`）。
- 在**搜索框输入、数字输入框聚焦**时，不触发滑动切换。

### 3.2 页签
- 点击页签直接跳页，带 200ms 过渡。
- 当前页页签高亮，其余灰色。
- 页签上显示已选数量：`③ 确认（已选 3 项）`，数量为 0 时显示 `③ 确认`。

### 3.3 状态保持
- 切换页面**不得清空已选症状**。
- 从 P1 识别出的症状，P3 清单里要立刻出现。
- 浏览器后退键：从 P2/P3 退回上一页，而不是直接离开站点。

### 3.4 提交
- P3 的「查看可能情况」在已选 0 项时**禁用**（保持现有 `disabled` 逻辑）。
- P1 的「下一步」在已选 0 项时仍可点击，但点击后提示"先选一个症状"（用现有 `nluResult` 区域显示，不要弹窗）。

### 3.5 桌面端
- 宽度 ≥ 900px 时**保持三页结构**，但隐藏滑动手势说明，页签仍可用（鼠标可点击切换）。
- 不要为了桌面端单独写一套布局。

## 4. 技术实现建议（推荐方案 A）

### 方案 A：CSS Scroll Snap（推荐）
```html
<div class="pages" id="pages">
  <section class="page" id="page-1">…</section>
  <section class="page" id="page-2">…</section>
  <section class="page" id="page-3">…</section>
</div>
```
```css
.pages{
  display:flex;
  overflow-x:auto;
  scroll-snap-type:x mandatory;
  overscroll-behavior-x:contain;   /* 防止触发浏览器前进/后退手势 */
  -webkit-overflow-scrolling:touch;
  scrollbar-width:none;
}
.pages::-webkit-scrollbar{display:none}
.page{flex:0 0 100%; scroll-snap-align:start; min-width:0}
```
- 用 `scrollTo({left: index * width, behavior:'smooth'})` 做页签跳转。
- 用 `scroll` 事件 + `Math.round(scrollLeft / width)` 同步页签高亮（节流 100ms）。
- 优点：自带惯性与吸附，无需手写手势；无障碍友好。
- **注意**：`scroll-snap-type` 与内部纵向滚动可共存，但每个 `.page` 内部不要再出现横向滚动容器。

### 方案 B：transform 轨道 + pointer 事件（仅当方案 A 在 iOS 上有问题）
- 容器 `translateX(-index * 100%)`，`transition: transform .28s ease`。
- 监听 `pointerdown/move/up`，判断横向意图后 `preventDefault`。
- 成本更高，除非方案 A 实测有问题，否则不要用。

## 5. 需要同步修改的地方（务必逐条检查）

1. **第 3 页的年龄与用药块**：从 P1 移到 P3（DOM 移动，事件绑定不用改）。
2. **提交按钮**：`#go` 移到 P3；P1/P2 各加一个「下一步」按钮，内部调用同一段跳页逻辑。
3. **`updateCount()`**：除了更新 `#count`，还要更新页签上的数量文案。
4. **深链 `#s=…`**：命中深链时直接渲染结果页（现有逻辑不变），不要先闪一下 P1。
5. **3D 视图**：切到别的页时必须暂停渲染循环（`requestAnimationFrame` 取消或暂停），切回来再恢复，避免后台空转耗电。
6. **`sw.js`**：缓存版本号 `v5` → `v6`（改完 HTML 必须升版本，否则老用户看缓存）。
7. **`aria`**：每个 `.page` 加 `role="group"` 与 `aria-label`（页标题）；页签用 `role="tab"` / `aria-selected`。

---

## 6. 不要做的事

- ❌ 不要引入 React / Vue / 任何框架或打包工具（本项目是单文件、零依赖）。
- ❌ 不要拆成多个 HTML 文件（多页会破坏离线缓存与深链）。
- ❌ 不要用整屏 `100vh` 锁死高度（iOS 地址栏会抖动），页高随内容自适应，纵向滚动交给 `body`。
- ❌ 不要删除现有的「查看全部 81 个症状」折叠、人体图层、3D 懒加载、随访横幅。
- ❌ 不要把 `position:fixed` 的对话框（档案、提醒）放进 `.pages` 内部，会和 transform/scroll 冲突——它们应保持在 `body` 直属层级。
